# Paper Research

Load for the `papers` branch in N2-N4.

## Evaluation contract

State the baseline, outcome metric, guard metrics, resource limits, transfer
assumptions, and the observation that would reject each approach. Marketing or
author prestige is never an outcome metric.

## Researcher trails

Query the claim, task, dataset, metric, and known baseline in several
formulations. For each useful paper record version, venue or archive, date,
authors, affiliations, the citations that shaped the method, later work that
tested it, and project, code, and data links.

Follow author and lab trails to later experiments, negative results, talks, and
demos. Follow repository contributors and issues when the code diverges from
the paper. Search independent replications and critiques before accepting the
authors' evaluation. Talks and demos clarify setup but never replace a protocol
or result table. Founder-authored papers and vendor demos are one lineage.

## Qualification

Score relevance, evidence quality, independent replication, artifact
availability, evaluation comparability, resource fit, and vendor or hardware
dependency. When adoption depends on a foreign vendor, proprietary device, or
hosted API, compare lock-in, reproducibility, cost, data handling, and a local
fallback before ranking.

## Normalization

Normalize each result by task, dataset split, baseline, metric definition,
compute or hardware, sample count, uncertainty, and ablation coverage. When
datasets, baselines, or metrics differ, do not rank headline gains: give a
provisional feasibility order at low confidence and propose the smallest
normalization or reproduction experiment.

## Experiment slate

Each experiment names the hypothesis, baseline, controlled variables, protocol,
metrics, artifacts, falsifier, stop condition, expected information gain, cost,
and duration, plus the result that promotes, revises, or stops it.
