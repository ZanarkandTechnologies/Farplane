# Interior Composition

Use this reference after the interior-design branch is selected.

## Interior Program

Before composing objects, define what the interior must support:

- occupants or agents and their scale;
- activities, duration, concurrency, and equipment;
- zones and important adjacencies;
- arrival, circulation, sightlines, and interaction clearances;
- fixed shell, camera, navigation, and technical constraints;
- focal anchors, storage, shared infrastructure, and transition areas.

The program explains why each zone and mass exists. Decorative props do not
substitute for a missing program.

## Evidence-First Scene Inventory

Record observed facts and missing evidence for:

- shell, floor, walls, thresholds, openings, and architectural rhythm;
- default camera, crop, viewport occupancy, and occlusion;
- primary visual masses and the largest uninterrupted voids;
- circulation paths, useful clearances, entrances, and interaction points;
- occupant, furniture, landmark, and room-scale relationships;
- silhouette families, repetition, variation, and focal hierarchy;
- material, value, color, furniture, lighting, and shadow language;
- zones that belong to one interior versus elements that read as pasted on.

When evidence is missing, options remain hypotheses. The next artifact should
make the uncertainty visible rather than hiding it in confident prose.

## Density And Negative Space

Treat density as a relationship between occupied mass, room envelope,
circulation, camera framing, and object scale. Distinguish:

- purposeful negative space: routes, thresholds, staging, visual focus, or
  operational clearance;
- dead space: large residual patches with no path, activity, anchor, or
  compositional role;
- clutter: objects without program value, hierarchy, or circulation respect.

Useful hypotheses may include occupied-mass range in the default view, maximum
contiguous dead patch, primary and secondary path widths in occupant units,
landmark-to-furniture scale, adjacency distance, and how much of the viewport
the meaningful interior occupies. These are blockout tests, not universal
standards.

## Composition Models

Present two or three structurally different models, not color variants. Useful
differences include:

- continuous floorplate with embedded neighborhoods;
- clustered program blocks connected by a circulation spine;
- perimeter work zones around a purposeful shared core;
- front/back or public/private workflow split;
- compact cutaway rooms when enclosure itself serves the experience.

Recommend one model and name what it sacrifices. After repeated local fixes or
an explicit negative rating, reset the composition model instead of preserving
failed geometry by default.

## Shared Interior Grammar

Define one coherent system for:

- room envelope and partition language;
- furniture proportions, construction, and repeated modules;
- material and value family;
- lighting direction, contrast, and shadow softness;
- base versus accent color roles;
- signage, storage, utilities, and shared infrastructure;
- how functional zones vary without becoming separate themed worlds.

## Reference Transfer

If actual reference media is available, compare composition, silhouette, value
structure, material family, lighting, density, and repetition. Map each trait
to `adopt`, `adapt`, `preserve`, or `reject`. If media is unavailable, state
that limitation and request it before locking direction. Never reduce reference
matching to a palette swap or literal asset copy.

## Review Artifact And Acceptance

Produce one artifact that exposes the spatial decision: annotated screenshot,
top-down or ASCII plan, greybox, isometric overlay, or side-by-side study. Show
shell, zones, masses, circulation, dead space, camera crop, and shared interior
grammar.

The operator accepts the artifact before a broad implementation pass. Route
reachability, collision, compile, console, performance, and accessibility are
necessary guardrails but do not prove taste or coherence.
