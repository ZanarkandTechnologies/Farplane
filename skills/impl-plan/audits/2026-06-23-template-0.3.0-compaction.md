# Skill Audit

## Change

- Before: `impl-plan/SKILL.md` was a 574-line first-load document with repeated
  workflow explanation, detailed plan shape, applicability rules, gotchas, and
  quality gates.
- After: `impl-plan/SKILL.md` follows the skill template 0.3.0 shape in 182
  lines: context, signature, phase boundary, todo list, templates, gotchas,
  reference map, and output.
- Why: oversized first-load context increases drift and compaction risk; the
  normal invocation only needs gates, routing, stop conditions, and reference
  load points.
- Tradeoff accepted: detailed ticket body and review detail stay in
  `references/template.md`, `references/review.md`, `prompts/plan.md`, and
  `qa_checklist.md` rather than being duplicated in first load.

## First-Principles Reasoning

- Objective: migrate `impl-plan` to the latest skill template and remove
  first-load fluff while preserving planning behavior.
- Placement logic: `SKILL.md` owns every-invocation contract; references own
  conditional drafting/review detail; `qa_checklist.md` owns material plan
  guardrails.
- Expected behavior delta: agents load a shorter planner, then load precise
  references only when drafting or checking the material plan.
- Proof needed: structure checklist, line count, validator, live reinstall, and
  installed-copy inspection.
