# QA Skill Template 0.3.8 Audit

## Change

- Before: the QA behavior was current, but `SKILL.md` did not declare the
  current skill template, used older contract-specific top-level sections, and
  exposed unnumbered todos that the surface-budget tooling counted as zero.
- After: the skill declares `skill-template: "0.3.8"`, follows the current
  section shape, and expresses the same workflow as eight numbered top-level
  todos.
- Why: align the skill's file format and registry metadata with the current
  Farplane template without changing QA behavior.
- Tradeoff accepted: the canonical receipt example remains first-load visible
  because moving it would increase defer-loading risk for every QA run.

## First-Principles Reasoning

- Objective: make the skill structurally truthful and maintainable.
- Placement logic: invocation-critical policy stays in `SKILL.md`; no new
  reference or eval surface is needed for a format-only migration.
- Expected behavior delta: none.
- Proof needed: template metadata, numbered-todo budget, registry, link,
  checklist, and diff-format checks. Behavioral eval was explicitly skipped.
